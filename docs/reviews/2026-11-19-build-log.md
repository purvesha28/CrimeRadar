## Decisions

| Decision | Reason |
|---|---|
| Keep Java servlets + Tomcat 9 + MySQL; UI as plain ES modules + Leaflet | Fits the CS 5200 course and the team's Eclipse setup; no build step |
| OpenStreetMap tiles + CSS filters (not CARTO) | CARTO basemaps now show "API KEY REQUIRED" |
| Load every offense of the last 4 years (about 319,000), not the newest 150,000 | Better time-of-day model; the user asked for 4 years |
| Risk levels: Elevated >= q90, High >= q97 (was q75/q90) | Risk is very skewed; with q90 all of downtown was "high" |
| Offenses at exactly 00:00:00 are "unknown time" and left out of time-of-day counts and the model | 8.6% of rows; they made Night look 40% worse |
| Route score: log scale up to the riskiest block-time | A q99 cap gave every downtown evening route 100 |
| Route counts use mode-relevant crime types (street crime for walk/bike; assault, robbery, vehicle crime for car) | Car break-ins do not threaten a pedestrian |
| Theme follows the clock (dark for evening and night) | Exhibition "wow" moment; matches the time-aware story |

| Route colors on the map (user request): green = recommended, orange = moderate, red = most dangerous; all routes drawn at once with "R · min" labels | The user asked for it; cards, labels and legend use the same colors, with text tags so color is never alone |

| Vector map (MapLibre GL + OpenFreeMap) with own day/night palettes, GPU heatmap, 3D risk skyline, Play the day, radar blips, route flow dash, login orbit; Leaflet kept as fallback (`?map=leaflet`) | User asked for a more attractive, "beautiful to watch" map; the fallback keeps the exhibition safe if WebGL or the tile service fails |
| Heatmap kernel: radius ~2.4x the cell spacing, intensity ~0.9 | Measured: smaller radius showed a grid of dots; the kernel math is in a code comment in `mapview-gl.js` |
